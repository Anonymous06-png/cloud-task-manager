## What is measured and what is not

This package was read off one rendered page. That page can show what a design *looks like*
and nothing about what it is *for*, so the two halves below are not equally trustworthy.

### Measured from the page

- every color role — background, surface, text, muted, border and accent — sampled from index.html by painted area and by characters of text
- the font families the page actually renders in (Inter)
- the body size (13px) and the h1 (29px), which set the 1.174 scale ratio
- the corner radii in use (8, 6, 12, 999px)
- the depth posture: 5 shadowed and 29 bordered elements
- the density (compact), derived from the measured body size
- the line height (1.5) and heading weight (650)

The raw numbers are in `reports/dna.json`, the capture that produced them in
`reports/metadata.json`, and `thumbnail.png` is the page they came from.

### Not measured — rewrite before publishing this as a brand system

- `name` — taken from the folder name or `--name`, not from the page.
- `mood` and `signature` — generated sentences restating the measurements above. Rewrite them in your own words before publishing this as a brand system.
- `use_for` / `avoid_for` — placeholders that say only "the design this came from". What a system suits is a judgement; nothing in a rendered page can supply it.
- `colors.success` / `colors.warning` / `colors.danger` — kit defaults for a light system. The page did not declare feedback colors; replace them with your real ones.
- `motion` — always `minimal`. Rendered CSS does not reveal a motion posture, so durations and easing here are a safe default, not an observation.
- `fonts.mono` — `JetBrains Mono`, a kit default. Set it to whatever your code blocks really use.
- No component inventory. `components.html` lists the landmarks and repeated class names observed in the source page; that is structure, not a specified set of components with variants, states and token bindings. This package deliberately ships no `components.json`.
